# Adaptive Multi-Strategy EA（MT5）

相場状況（トレンド／レンジ／中立／高ボラティリティ）を自動で判定し、
4つの売買ロジックの重みを切り替えて売買する MetaTrader 5 用 EA です。
デフォルトは **USDJPY / H1**、ブローカーは **OANDA（デモ口座）** を想定しています。

> ⚠️ このEAは利益を保証するものではありません。FX は元本を超える損失が出る可能性があります。
> 必ず **デモ口座** で十分に検証してから、自己責任でお使いください。

---

## 推奨設定：東京仲値モード（USDJPY・5分足）

これまでの検証で、コストを上乗せしても、見ていない期間で利益が続いた唯一の設定です。
検証の経緯と全結果は `reports/experiments.md` にあります。

### 売買のルール
- **ゴトー日**（5・10・15・20・25・30日と月末）だけ取引します。
  - その日が土日・日本の祝日・年末年始のときは、直前の東京の営業日に前倒しします。
  - 2015〜2028年の祝日は内蔵しています。それ以外の年は `InpJPHolidays` で追加してください。
- 東京時間 **9:55（仲値の公表時刻）に USDJPY を売り**、**12:00 に決済**します。
- SL は固定30pips、TP はなし（時刻で決済）です。
- 根拠：ゴトー日は輸入企業のドル買いが仲値に集中しやすく、仲値の後にその反動でドル円が下がりやすい、という実需の動きです。
- 時刻はサーバー時間から自動で東京時間に直します（アメリカの夏時間にも対応）。

### 使い方
1. EA を **USDJPY の5分足** チャートに貼り付けます。
2. 「パラメータの入力」タブの「読み込み」で `MQL5/Presets/AMS_TokyoFix_USDJPY.set` を選びます。
3. 取引は月6回ほどです。9:55（夏時間は同じ東京時刻）の前に MT5 が動いている必要があります。

### バックテストの成績（OANDA デモ口座の履歴、初期資金100万円）

| 期間 | 役割 | 条件 | 総損益 | PF | 取引数 | 最大DD | 月平均 |
|---|---|---|---|---|---|---|---|
| 2015〜2021年 | 設計 | 1分足OHLC・リスク1% | +396,222円 | 1.60 | 510 | 8% | +0.41% |
| 2022年〜2024年10月 | 検証 | 1分足OHLC・リスク1% | +148,536円 | 1.43 | 218 | 5% | +0.42% |
| 2024年11月〜2026年11月 | 最終確認 | **リアルティック**・リスク1% | +119,403円 | 1.45 | 149 | 5% | +0.46% |
| 〃 | 〃 | リアルティック・**リスク3%（プリセットの値）** | +329,165円 | 1.43 | 149 | 9% | +1.17% |

- いずれも、1取引あたり 0.5 pips 不利に約定したと仮定してもプラスです。
- リスク4%・5%にしても、月平均は +1.2% 台でほぼ増えません。
  - 必要証拠金の上限（有効証拠金の40%）でロットが頭打ちになるためです。

### 期待しすぎないでください
- **月+10% には届きません。** 最終確認期間の月平均はリスク3%で約 +1.2%、最も悪い月は約 -3% でした。
- 1回あたりの利益は小さく、スプレッドや約定のずれに影響されます。
  - バックテストには、注文の遅れと実際のスプレッド（リアルティック）を入れています。
  - それでも、実際の口座とは差が出ます。
- 実需の流れが変われば、この傾向が消える可能性があります。
- 実運用の前に、**OANDA デモ口座で最低1〜2か月**動かしてください。
  - バックテストと同じくらいの成績（月6回前後の取引、勝率5割強）になるかを確認します。

## 高リスクの選択肢：時間帯の7ルールの組み合わせ（研究段階）

月の利益を増やすため、東京仲値の前後の「時間帯・需給の偏り」6本に、ロンドンの朝のユーロ売り（A1）を加えた設定です。
上の推奨設定よりも利益は大きい一方、**DD もずっと大きく、まだ研究段階**です。

- プリセット：`MQL5/Presets/AMS_Calendar_Portfolio.set`（**USDJPY の5分足** に貼り付け。EURJPY・GBPJPY・EURUSD も同時に取引します）
  - A1 を除いた6ルールだけの控えめな設定：`MQL5/Presets/AMS_Calendar_Portfolio_6rules.set`
- ルール（書いた順が優先順位）：
  - G3F：USDJPY をゴトー日 9:55 に売り、12:00 に決済。ただし、仲値前30分（9:25〜9:55）に下げていた日は見送ります。
  - P2：EURJPY をゴトー日 9:25 に買い、9:55 に決済
  - P4：EURJPY を金曜 9:25 に買い、9:55 に決済
  - Q2：EURJPY をゴトー日 9:55 に売り、12:00 に決済。ただし、仲値前30分に大きく上げた日だけです。
  - C3：EURJPY を月末 10:00 に売り、11:00 に決済
  - C4：GBPJPY を月初の2平日の 22:00（東京時間）に売り、24:00 に決済
  - A1：EURUSD を毎日ロンドン 11:00 に売り、13:00 に決済（月に約21回）
    - 3つの期間すべてでプラスでした。ただし、設計期間の +0.5 pips 込みの PF が 1.07 で、決めていた合格ライン（1.10）には届いていません。
    - 取引回数を増やして利益を伸ばすために加えています。その分、DD と最悪の月は大きくなります。

7ルールと6ルールの比較（初期資金100万円、月間目標は「届いたら半分」）：

| 期間 | 7ルール：損益／月平均／最大DD／最悪の月 | 6ルール：損益／月平均／最大DD／最悪の月 |
|---|---|---|
| 2015〜2021年 | +2,263万円／+4.21%／31%／-23.9% | +1,301万円／+3.45%／21%／-13.0% |
| 2022年〜2024年10月 | +1,797万円／+9.60%／22%／-13.2% | +841万円／+7.26%／19%／-11.1% |
| 2024年11月〜2026年11月 | +218万円／+5.26%／33%／-12.3% | +99万円／+3.13%／26%／-8.7% |

以下の表と説明は、6ルールの成績です。
- リスク4%、必要証拠金の上限90%。すべての建玉が損切りに達しても、証拠金維持率が120%以上残るロットまでに抑えます（OANDA のロスカットは維持率100%）。

- 仲値前の値動きの条件は、Krohn ほか（*Journal of Finance* 2024）の「フィキシング前の米ドル高は、フィキシング後に戻される」という研究にもとづきます。

| 期間 | 条件 | 月平均 | 幾何平均 | 最大DD | 最悪の月 | +0.5pips時 PF |
|---|---|---|---|---|---|---|
| 2015〜2021年（設計） | 1分足OHLC | +3.68% | +3.39% | 22% | -13.1% | 1.40 |
| 2022年〜2024年10月（検証） | リアルティック | +7.96% | +7.42% | 19% | -10.9% | 1.77 |
| 2024年11月〜2026年11月（**参考**） | リアルティック | +3.78% | +3.31% | 29% | -9.2% | 1.18 |

- 6ルールとも、作るときに使わなかった期間（2024年11月〜）でもプラスでした。
  - 別の仕組みのルール（ロンドン16時の W1、週明けの窓の GW）も試しました。設計・検証期間では合格でしたが、使っていなかった期間でどちらも負けたため、外しています。
- 仲値の直後の数秒で値が動くため、注文は足の始まりにすぐ出します（`InpEntryDelaySec=0`）。
- 設計・検証期間の月ごとの損益率から作ったモンテカルロ分析（`tools/montecarlo.py`）では、1年後に損失になる確率は約3%、月平均 +5% 以上になる確率は約3分の1でした。

- **月間目標の利益確保**：その月の利益（月初の残高比）が +5% に届いたら、月末までロットを半分にして取引を続けます（`InpMonthTargetPct=5`、`InpMonthLockMul=0.5`）。
  - +5% に届いた月の利益を守りつつ、その後の上振れも半分は取ります。
  - 3つの形の比較（初期資金100万円。月平均／+5%以上の月の割合／損益）：

| 期間 | ロックなし | 届いたら止める（0） | 届いたら半分（**0.5、推奨**） |
|---|---|---|---|
| 2015〜2021年 | +3.68%／33%／+1,541万円 | +3.06%／49%／+943万円 | +3.45%／39%／+1,301万円 |
| 2022年〜2024年10月 | +7.96%／65%／+1,041万円 | +4.19%／68%／+274万円 | +7.26%／65%／+841万円 |
| 2024年11月〜2026年11月 | +3.78%／32%／+125万円 | +1.25%／40%／+32万円 | +3.13%／40%／+99万円 |

  - 「届いたら止める」形は、2024年11月〜の利益が小さくなりすぎました。そのため、半分にして続ける形を推奨にしました。
  - 月平均を最も重視する場合は、`InpMonthTargetPct=0`（ロックなし）にしてください。
- **自動調整（安全装置）**：各ルールのシグナルを「仮想の取引」として記録し続けます。直近100回の成績（コスト後の PF）が 0.9 を下回ったルールは、自動で注文を止めます。成績が戻れば自動で再開します。
  - 記録はファイルに保存されるので、MT5 を再起動しても引き継がれます。
  - 2015〜2026年の通しのテストで、後で崩れたルール（R4・F2）を自動で止め、利益を減らさずに PF を 1.37 → 1.45 に上げました。
  - 直近40回など短い記録で判断すると、一時的な不調で止めて回復を取り逃がし、かえって成績が下がりました。
- **月+5% に安定して届く設定ではありません。** 3つの期間の月平均は +3.7%〜+8.0% で、+5% を超えたのは検証期間だけでした（3期間の単純平均は約 +5.1%）。
- 最後の期間は「参考」です。この期間は、別の組み合わせの最終確認ですでに一度使っています。その結果を見て、2本のルール（R4・F2）を外しました。そのため、まだ見ていない期間での成績とは言えません。
- 1か月で -13% 前後、最高値から 20〜30% の下落が起こりえます。強制ロスカットはどの期間でも0回でしたが、損切りが大きく滑ると余裕は小さくなります。
- 実際に使う前に、OANDA デモ口座で数か月動かし、成績を確かめてください。

## デモ口座での実運用（フォワードテスト）

GitHub Actions の `MT5 Live (OANDA demo)`（`.github/workflows/mt5-live.yml`）で、OANDA デモ口座に推奨設定（`AMS_Calendar_Portfolio.set`）の EA を動かしています。

- 約5.5時間ずつ動かし、終わる前に次の回を起動して、途切れずにつなぎます。
  - 東京の朝（日本時間 9:00〜12:10）と C4 の時間（日本時間 21:35〜24:10）には、入れ替わりの切れ目が来ないようにしています。
- 成績は `reports/live/summary.md`（月ごとの損益・ルールごとの成績・残高）に、毎回自動でまとめます。
  - 取引の記録は `reports/live/AMS_live_deals.csv`、残高の推移は `reports/live/AMS_live_account.csv` です。
  - 口座番号やパスワードは、公開されるファイルに書き出しません。
- 止めるには：リポジトリの Settings → Secrets and variables → Actions → Variables に `LIVE_ENABLED` = `false` を作ります。実行中の回は、Actions の画面で Cancel します。
- EA を再起動しても、自動調整の記録・月初の残高・保有中のポジションの決済時刻は引き継ぎます。

## 仕組み

### 1. 相場状況の判定（`MQL5/Include/AMS/Regime.mqh`）
確定足を使って、次の順番で判定します。

| 判定 | 条件（デフォルト） |
|---|---|
| 高ボラティリティ | ATR(14) が直近100本の上位10%（順位 ≥ 0.90） |
| 強いトレンド | ADX(14) ≥ 25、かつ EMA50/EMA200 の傾き・並び・終値の位置がそろっている |
| レンジ | ADX(14) < 20、かつ BB(20, 2σ) の幅が直近100本の中央値以下 |
| 中立 | 上のどれでもない |

### 2. 売買ロジック（`MQL5/Include/AMS/Strategies.mqh`）
各ロジックは -1（強い売り）〜 +1（強い買い）のシグナルを出します。

| ロジック | 内容 |
|---|---|
| トレンドフォロー (TF) | EMA20/EMA50 のクロス（±1）、クロス後の押し目・戻り（±0.5）。H4 EMA200 に逆らう方向は無視 |
| ブレイクアウト (BO) | 直近20本の高値/安値を終値で抜けた（±1）。H4 の方向に逆らう場合は半分 |
| 逆張り (MR) | BB の外から内側へ戻り、RSI も極端（±1）。RSI 30/70 の抜け戻しのみ（±0.5） |
| モメンタム (MO) | MACD ヒストグラムの 0 ラインクロス。ストキャスティクスが同じ向きなら ±1、違えば ±0.5 |

### 3. 使い分け（重み）
相場状況ごとに重みを付け、`スコア = Σ(重み×シグナル) ÷ Σ重み` が
`InpEntryThreshold`（0.45）以上で買い、−0.45 以下で売りです。

| 相場状況 | TF | BO | MR | MO |
|---|---|---|---|---|
| トレンド | 0.50 | 0.30 | 0.00 | 0.20 |
| レンジ | 0.00 | 0.00 | 0.80 | 0.20 |
| 中立 | 0.30 | 0.25 | 0.15 | 0.30 |
| 高ボラ | 中立と同じ重み。ロットは半分（`InpHighVolMode` で「停止」にも変更可） |

- 判定は **新しい足ができたときだけ** 行います。
- 逆方向のシグナルが出たら、保有中のポジションを決済します（`InpCloseOnOpposite`）。
- ナンピンや積み増しはしません（最大ポジション数のデフォルトは 1）。

### 4. 資金管理（`MQL5/Include/AMS/RiskManager.mqh`）
- **ロット**：有効証拠金の 1%（`InpRiskPercent`）を、SL に掛かったときの損失額とします。
  - 損失額は `OrderCalcProfit` で計算するので、円口座でも正しく計算されます。
  - ロットはブローカーの最小ロット・最大ロット・刻み幅に合わせて調整します。
- **SL / TP**：SL = ATR×2.0、TP = ATR×2.0（最適化とフォワード検証の結果で決定。`reports/optimize_summary.md` 参照）。
- **建値ストップ**：含み益が ATR×0.5 に達したら、SL を建値＋0.5pips に移します。
- **トレーリング**：含み益が ATR×1.5 を超えたら、現在値から ATR×1.0 の位置で SL を追いかけます。
- **1日の損失上限**：損失が 3% に達したら、その日は新規エントリーをしません。

### 5. フィルター（`MQL5/Include/AMS/TradeFilters.mqh`）
- スプレッドが 2.0 pips を超えたら見送り
- 取引時間の指定（デフォルトは終日）
- 金曜 22時（サーバー時間）以降は全決済（週末持ち越しなし）
- 月曜 2時までは新規エントリーなし

## Windows の MT5 で使う手順

1. MT5 を起動し、メニューの「ファイル」→「データフォルダを開く」を選びます。
2. このリポジトリの `MQL5` フォルダの中身を、データフォルダの `MQL5` に上書きコピーします。
   - `MQL5/Experts/AdaptiveMultiStrategyEA.mq5`
   - `MQL5/Include/AMS/*.mqh`
3. MetaEditor（F4）で `AdaptiveMultiStrategyEA.mq5` を開き、「コンパイル」（F7）を押します。
   - エラー0になることを確認してください。
4. MT5 の「ナビゲーター」→「エキスパートアドバイザ」から、USDJPY の **1時間足** チャートにドラッグします。
5. 「アルゴ取引を許可」にチェックを入れ、ツールバーの「アルゴ取引」ボタンをONにします。

### OANDA の注意点
- 銘柄名に接尾辞が付く口座があります（例：`USDJPY.oj1m`）。
  - EA は貼り付けたチャートの銘柄（`_Symbol`）で動くので、そのまま使えます。
- 最小ロットや刻み幅はコースによって違います。
  - EA は口座の設定を読み取って自動で合わせます。
  - 計算したロットが最小ロット未満になる場合は、エントリーを見送ります。
  - それでも最小ロットで入りたい場合は、`InpAllowMinLot = true` にしてください（リスクが設定より大きくなります）。
- 取引時間・金曜クローズの時刻は **サーバー時間** です。OANDA のサーバー時間に合わせて調整してください。

### MT5 の画面でバックテストする
1. 「表示」→「ストラテジーテスター」（Ctrl+R）を開きます。
2. 次のように設定します。

   | 項目 | 設定 |
   |---|---|
   | エキスパート | `AdaptiveMultiStrategyEA` |
   | 銘柄 | `USDJPY`（接尾辞付きの場合はその名前） |
   | 時間足 | H1 |
   | 期間 | 直近2年など |
   | モデル | 「1分足OHLC」または「全ティック」 |
   | 初期証拠金 | 1,000,000 JPY |

3. 「開始」を押します。
   - 終了後、「操作ログ」に相場状況別・ロジック別の成績が `[AMS]` で表示されます。
   - 同じ内容が `Common/Files/AMS_breakdown.csv` にも出力されます。
4. 最適化をするときは、「最適化基準」を「カスタム最大」にしてください。
   - EA の `OnTester` が「PF × √取引数 ÷ (1 + 最大DD%/10)」を返すので、DD が小さく安定した設定が上位に来ます。
   - 過去データに合わせすぎないよう、期間の後半をフォワードテストに分けることをおすすめします。

## Linux（Wine）で動かすスクリプト

画面のない Linux サーバーでも、Wine と Xvfb で MT5 を動かせます。

```bash
bash tools/install_mt5.sh          # Wine・Xvfb・MT5 を導入
bash tools/compile.sh              # MetaEditor でコンパイル（エラー0・警告0を確認）

cp tester/credentials.env.example tester/credentials.env
# tester/credentials.env に OANDA デモ口座の ID・パスワード・サーバー名・銘柄名を書く（git 管理外）
bash tools/backtest.sh             # 直近2年をバックテスト → reports/ に保存
bash tools/backtest.sh 2023.01.01 2025.12.31   # 期間を指定する場合
```

- 結果は `reports/summary.md`（要約）、HTML レポート、`AMS_breakdown.csv` に保存されます。
- OANDA の MT5 インストーラーを使いたい場合は、`MT5_INSTALLER_URL` にその URL を指定して `install_mt5.sh` を実行してください。
- ログイン情報は、`tester/credentials.env`（`.gitignore` で除外）と、実行中だけ作る一時ファイルにしか書きません。
  - 一時ファイルは、終了時に削除します。

## GitHub Actions でバックテストする（PC不要・スマホから実行可）

`.github/workflows/mt5-backtest.yml` は、Windows ランナー上で次の3つを行います。
1. MT5 をインストールする
2. EA をコンパイルする（エラー0・警告0を確認）
3. OANDA デモ口座にログインして、ストラテジーテスターを実行する

### 初回だけの設定（スマホのブラウザでも可）
1. GitHub でリポジトリを開き、**Settings → Secrets and variables → Actions** に進みます。
2. 「**New repository secret**」で、次の3つを登録します。

   | 名前 | 内容 |
   |---|---|
   | `MT5_LOGIN` | OANDA デモ口座のログインID（数字） |
   | `MT5_PASSWORD` | デモ口座のパスワード |
   | `MT5_SERVER` | MT5 のログイン画面に表示されるサーバー名（例：`OANDA-Japan MT5 Demo`） |

3. （任意）**Variables** タブで、次の変数を登録できます。
   - `MT5_SYMBOL`：銘柄名に接尾辞がある場合（例：`USDJPY.oj1m`）
   - `MT5_INSTALLER_URL`：別の MT5 インストーラーを使う場合
     - 既定は OANDA 版（`oanda.corporation/mt5/oanda5setup.exe`）です。
     - OANDA のサーバー一覧が入っているので、サーバー名でログインできます。

### 実行
1. **Actions** タブで「MT5 Backtest」を選び、「**Run workflow**」を押します。
   - 期間・銘柄・モデルは、その場で指定できます。
2. 終わったら、実行結果の **Summary** に成績の要約が表示されます。
   - HTML レポートやログは「**mt5-backtest-reports**」からダウンロードできます。

### 最適化（mode = optimize）
- 「Run workflow」で `mode` に **optimize** を選ぶと、遺伝的アルゴリズムで最適化します。
  - 対象は `tester/optimize_inputs.ini` に書いたパラメータです。
  - 評価には EA の `OnTester` が返すカスタム評価値を使います。
- 期間の後半（既定では直近10か月）は、**最適化に使わないフォワード検証期間**にします。
  - 両方の期間で利益が出た設定だけを、`reports/optimize_summary.md` に一覧表示します。
- 過去データに合わせすぎた設定を選ばないよう、フォワード期間の成績を重視してください。

### 補足
- シークレットが未設定の場合は、コンパイルだけ行います。
- `MQL5/` を変更してプッシュすると、自動で実行されます。
- シークレットの値は GitHub がログ上で伏せ字にします。テスターの設定ファイル（パスワードを含む）は、実行後に削除します。

## 主なパラメータ

| パラメータ | 既定値 | 説明 |
|---|---|---|
| `InpTimeframe` | H1 | 判定に使う時間足 |
| `InpEntryThreshold` | 0.45 | エントリーに必要なスコア |
| `InpRiskPercent` | 1.0 | 1回の許容損失（%） |
| `InpSLATR` / `InpTPATR` | 2.0 / 2.0 | SL/TP の ATR 倍率 |
| `InpMaxDailyLossPct` | 3.0 | 1日の損失上限（%） |
| `InpMaxSpreadPips` | 2.0 | 最大スプレッド |
| `InpHighVolMode` | ロット半分 | 高ボラ時の扱い（停止 / ロット半分） |
| `InpUseTrend` ほか | true | 各ロジックの ON/OFF |
| `InpWTrend_TF` ほか | 上の表 | 相場状況ごとの重み |
| `InpVerbose` | false | 毎バーの判定内容をログに出す（検証用） |
